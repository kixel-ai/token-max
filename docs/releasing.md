# Release preparation

token-max ships as the `token-max` crate on crates.io and as prebuilt
binaries on a GitHub Release with the same `v<version>` tag. Nothing is
published by a PR, tag, or merge. m0 owns the 0.1.0 version change, full
end-to-end validation, publication after every child merges, and
verification of the published first-use commands. `Cargo.toml` is the only
version source, `--version` reports it, and the development version stays
0.0.0, which the release preflight refuses.

The read-only `Check` workflow runs `just check` (formatting, clippy with
warnings as errors, the synthetic tests and `quest check`) on Linux, and the
tests on macOS and Windows. The required `Check` job aggregates them; failed,
cancelled, or skipped dependencies fail it, so a skipped draft run cannot
satisfy the gate. PR jobs have no publication credentials or OIDC permission.

## Binaries

[cargo-dist](https://github.com/axodotdev/cargo-dist), configured in
`dist-workspace.toml`, builds the release assets. The **Release** workflow is
written by hand rather than generated by `dist generate`, so that it keeps
the protected path below; it calls `dist build` for each target and once more
for the installers.

| Target | Runner |
| --- | --- |
| `x86_64-unknown-linux-musl` (static) | `ubuntu-24.04` |
| `aarch64-unknown-linux-musl` (static) | `ubuntu-24.04-arm` |
| `aarch64-apple-darwin` | `macos-15` |
| `x86_64-apple-darwin` | `macos-15` |
| `x86_64-pc-windows-msvc` | `windows-2025` |

Each release carries, per target, `token-max-<target>.tar.xz` (a
`token-max-<target>/` directory holding the binary, README and LICENSE) or,
on Windows, a flat `token-max-<target>.zip`, each with a `.sha256` file;
`token-max-installer.sh` and `token-max-installer.ps1`, which install into
the first of `$XDG_BIN_HOME`, `$XDG_DATA_HOME/../bin` and `~/.local/bin`; `source.tar.gz`; and `sha256.sum` over the archives. Every
asset gets a GitHub build provenance attestation, which
`gh attestation verify <file> --repo kixel-ai/token-max` checks.
`[package.metadata.binstall]` in `Cargo.toml` points `cargo binstall` at the
same archives.

The shell installer embeds each archive's checksum and refuses a mismatch,
but skips the check, saying so, on a system without `sha256sum`.
cargo-dist's PowerShell installer checks nothing. Where either applies,
verify the archive against `sha256.sum` or with `gh attestation verify`.

The flake's default package builds from source and needs no release:
`nix run github:kixel-ai/token-max`.

To upgrade cargo-dist, change `cargo-dist-version` in `dist-workspace.toml`
and `DIST_VERSION` in `release.yml`, and replace every pinned SHA-256 in
`release.yml` (each matrix `dist-sha256` and the `installers` job's
`sha256`) with the matching line of that release's `sha256.sum`.

## Release setup

Two GitHub environments hold the release's write access, each restricted to
**only the branch `main`**:

- `github-releases` creates and publishes the GitHub Release
  (`contents: write`, plus attestations). It holds no secrets.
- `crates-io` publishes the crate. Publication credentials live only in this
  environment, never in repository secrets, PR jobs, or checkout files.

crates.io creates a trusted publisher only for a crate that already exists,
so the first release publishes with a token:

1. For the first release, create a short-lived crates.io API token with the
   `publish-new` scope, store it as the `crates-io` environment secret
   `CARGO_BOOTSTRAP_TOKEN`, and dispatch with `bootstrap`. Revoke the token
   and delete the secret afterwards.
2. Then add a trusted publisher on the crate's crates.io settings for owner
   `kixel-ai`, repository `token-max`, workflow `release.yml` and
   environment `crates-io`. Later releases use the default `trusted` mode,
   where `rust-lang/crates-io-auth-action` exchanges the job's OIDC token
   for a temporary publish token and revokes it when the job ends.

An agent can drive Chrome through crates.io owner setup when requested; login
and crate ownership still belong to the owner. Do not send credentials in chat.

## Publish

After all m0 children merge, m0 sets the version in `Cargo.toml` to 0.1.0
through the protected, reviewed squash path, validates the complete tool, and
updates the README's pre-release notice in that change.

Dispatch **Release** on protected `main` with that exact version. Preflight
refuses 0.0.0, a prerelease (the release is always marked latest, which the
installers serve), a mismatched version, and a version crates.io already
has. `draft` refuses an existing tag on another commit. Then, in order:

1. The complete Check workflow and every target's build run.
2. The installers and `sha256.sum` are built from all the archives.
3. `draft` attests every asset and uploads it to a draft release, which is
   not public and creates no tag. Until `publish` succeeds, a retry, even
   from a later commit, reuses the draft and moves it to the new commit.
4. `publish` runs `cargo publish --locked` from the restricted environment.
5. `announce` publishes the draft as the latest release, which creates the
   tag at the dispatched commit.

A failure before step 4 leaves nothing public. crates.io cannot be undone,
so it goes after everything that can fail is staged; if `announce` fails,
rerun it in the same run, since preflight refuses a new run for a version
crates.io has. Inspect the package first with `cargo publish --locked --dry-run`
and `cargo package --list`.

To check a change to the release itself, dispatch **Release** from its
branch with `dry-run` and the branch's `Cargo.toml` version (0.0.0 is
allowed). It builds every archive and installer and uploads them as workflow
artifacts; the jobs that publish only run on `main` without `dry-run`.

After publication, run both installers from a clean home without a Rust
toolchain, and `cargo binstall token-max` and `cargo install --locked
token-max` from a clean `CARGO_HOME`; verify help, version and a synthetic
priced analysis for each. Then clear m0's publication wait and Quest's
release handoff. A failed publish is a release failure, never permission to
publish an incomplete placeholder.

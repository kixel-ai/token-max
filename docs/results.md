# Results on the maintainer's machines

The README and [max.kixel.ai](https://max.kixel.ai) lead with figures from
`token-max doctor --details --since 2026-10-18T23:25:26Z` and the same with
`--defaults`, run 2026-11-17 on each of the maintainer's four machines, a macOS
laptop and three Linux hosts, at commit `a90ee51`. They are a dated snapshot,
regenerated by hand; change all three together. Names of the maintainer's
private skills, MCP servers and paths are left out, and no prompt or reply text
is published.

## Totals

Each machine ran doctor on its own, since doctor asks how a profile pays only
on its own host, so these totals are its four reports added by hand, as
`doctor --ssh` adds hosts:

| Machine | Requests | Sessions | API cost | Potential savings |
| --- | --- | --- | --- | --- |
| Laptop (macOS) | 29,728 | 202 | ~$2,278 ± $14 | ~$122/mo, margin unknown |
| Workstation | 764,641 | 7,290 | ~$44,438 ± $70 | ~$1,160/mo ± $5.51 |
| Server | 203,993 | 1,993 | ~$12,947 ± $131 | ~$203/mo ± $2.61 |
| Second workstation | 183,483 | 2,591 | ~$10,346 ± $5.26 | ~$204/mo ± $0.88 |
| **All four** | **1,181,845** | **12,076** | **~$70,009 ± $149** | **~$1,689/mo, margin unknown** |

- **API cost** is every recorded Claude Code, Codex and T3 Code request at
  public API prices, extrapolated over the requests that could not be priced
  (`~`, with a 95% margin). The total's margin combines the machines' in
  quadrature, as doctor combines profiles. The machines are summed as they
  are: a history copied from one to another would count on both.
- **Sessions** count each Claude Code session and Codex thread once, with the
  subagents and review threads it spawned.
- **Potential savings** is the line under each `--defaults` report's
  headline: what every change doctor would make for a user with no settings
  files saves at the window's rate, recommended and worth considering alike,
  2% of the spend. 7 more changes, such as Codex's effort, could not be
  measured. Each saving holds the other settings constant, so overlapping
  changes may save less. The laptop's margin is unknown because one of its
  savings came from too few priced requests to measure a spread. ~$519/mo is a
  1h main-agent cache on the usage credits profiles, a Measured line. ~$386/mo
  is turning auto memory off, the maintainer's Opinion line. The rest is
  skills and built-in tools that were never used or cost more than $1 per use,
  led by the `dataviz` skill, the Workflow tool, the ScheduleWakeup tool and
  the `code-review` skill.

Against the maintainer's current settings, the changes doctor still offers save
~$758/mo. Their settings already save ~$515/mo against the defaults: the 1h
main-agent cache's ~$519/mo, less ~$3.63/mo that the 1h subagent cache on the
same profiles costs more than the default 5m.

doctor asked how each Claude profile pays, and each answer came from the
profile's account (`oauthAccount.billingType` in its `.claude.json`): every
machine's `~/.claude` is on a plan, and the usage credits profiles, plus an
archived profile with no account, were answered as API.

## Prompt cache TTL

Replays of the same sessions at 5m and 1h, summed over the four machines. Each
is a Measured line in its profile's `settings.json`; the cost is the cache's
over the 30 days.

| Setting | Profiles | 5m | 1h | 1h against 5m |
| --- | --- | --- | --- | --- |
| `subagentPromptCacheTtl` | plan, unset (5m) | ~$24,453 | ~$20,308 | ~17% less, ~$4,146 ± $30 |
| `promptCacheTtl` (main agent) | usage credits, set to 1h | ~$1,393 | ~$874 | ~37% less, ~$519 ± $2.08 |

On the plan profiles doctor shows both lines as "not enough evidence": the
replay favors 1h, but T3 Code shares those profiles' histories, and doctor
can't yet tell whether a T3 session ran under the profile's setting, so
neither is in the savings above. The ~$4,146 subagent saving joins them once
that is fixed, and this snapshot is retaken then.
[How context is priced](reference.md#how-context-is-priced) describes the
rule. On the usage credits profiles, which already set both to 1h, the main
agent's 1h is the ~$519/mo in the savings; on their few subagent requests 5m
was cheaper, by ~$3.63 over the window.

## Against T3 Code's count

T3 Code's usage page showed **$60,391.31 over 23,285 sessions** for its last
30 days, as an API estimate, read the same day. `token-max sessions`, run on
each machine over the window above, accounts for most of the difference:

- **Sessions.** T3 Code counts every transcript's session ID and every Codex
  rollout, so a Codex subagent or review thread is a session of its own. The
  export lists each session and subagent on its own line: 23,250 across the
  four machines, within 0.2% of T3 Code's count. doctor counts a subagent with
  the session that spawned it, which gives 12,076; the export's lines without a
  parent, plus the parents that ran before the window, agree with it exactly on
  two machines, within 3 sessions on the second workstation and within 3% on
  the server.
- **Cost.** T3 Code adds $0 for a request it cannot price; doctor extrapolates
  over them. The export's priced requests alone come to $65,375, 8% above
  T3 Code. The rest is how each prices and windows: T3 Code prices from
  LiteLLM's table and doctor from models.dev, and T3 Code's 30 days are local
  calendar days ending when it was read, several hours before these runs
  ended.

Neither is an invoice: on a plan, both measure what the usage would cost at
API prices.

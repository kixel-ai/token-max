# T3 evidence

The adapter was checked against T3 Code commit
[c4ce7b0](https://github.com/pingdotgg/t3code/commit/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165)
on 2026-11-08. It supports that revision's `providerInstances` settings envelope,
legacy `providers`, and V2 projection tables. Unknown providers are excluded
before their unrelated controls are decoded. Malformed supported controls or
unknown global policy values fail with a path-only diagnostic. Unknown/missing
projection schemas disable optional metadata without removing
native billed requests. This is not a complete T3 bill.

## Discovery and controls

[Server paths](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/config.ts)
place production state in `.t3/userdata` and development state in `.t3/dev`.
`T3CODE_HOME` selects the base, while `--t3-dir` selects a state directory directly.
Configured homes expand `~`; inherited environment paths remain literal, matching
[Claude home resolution](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/provider/Drivers/ClaudeHome.ts).
Codex uses its configured/shared home, or the inherited `CODEX_HOME` fallback
without a managed/shadow home. Its
[shadow layout](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/provider/Drivers/CodexHomeLayout.ts)
shares native histories and config; it does not add another bill. Canonical file
walks and native request identities handle overlapping homes and aliases.

The allowlist reads home paths, enabled state, idle controls, Claude window and
whether launch arguments exist. Environment values are decoded only for home,
cache, provider, compaction and Bash controls used by existing checks; secret or
sensitive relevant entries make ownership unresolved. Arbitrary values and
credential references are not decoded or exported. Launch argument text is not
retained. Desktop connection catalogs are not read.

[Settings](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/packages/contracts/src/settings.ts)
resolve global `idleCompaction`, then legacy `compactIdleThreads` (`true` means
`beforeCacheExpires`, `false` means `onReturn`), defaulting to `onReturn`.
Per-instance `default` inherits that global value. Either enabled flag can disable
an instance without deleting its history. A machine policy may replace settings
or homes: presence/access errors on Linux/macOS and unsupported Windows registry
policy make current ownership advisory and discovery coverage explicitly incomplete.

Claude's SDK window override takes precedence over native user/project windows;
without it, unverified project/launch fallback remains advisory. The
[Claude model compiler](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/claudeModelOptions.ts)
sets supported `fastMode` explicitly, default false. The
[Codex compiler](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/codexModelOptions.ts)
passes a selected service tier (or legacy fast selection); omission can inherit
native `service_tier`. Historical metadata does not establish the current thread
or browser composer selection. Unsupported/omitted historical capability data is
not converted into a billed speed.

## SQLite and native links

The adapter opens only an existing `statev2.sqlite` with SQLite read-only flags,
zero busy timeout, `query_only` and `trusted_schema=OFF`. It holds one read
transaction across schema validation and all allowlisted queries. Its bundled
SQLite needs no external installation. Native identities exist privately until
joining; exported thread/run/attempt/turn identities are opaque hashes.

Each lookup returns at most two matches so duplicates stay ambiguous. Real table
presence and selected columns are validated before queries. Malformed or orphan join rows remain unavailable/ambiguous individually, preserving other valid joins. SQLite value lengths
are limited to 1 MiB and each state has a ten-million VM-instruction budget.
Exceeding either bound is optional metadata unavailability, never a zero-cost
claim. SQL may compare exact `/compact` markers but returns no message text,
tool arguments, outputs or arbitrary JSON payloads.

Native provider thread/session and turn/item identities must join uniquely through
the same thread/provider-thread/attempt. Requested speed comes only from the first
V2 `run.updated` running event for that exact attempt and matching model. A later
steering event cannot fill an absent first selection. Conflicting native evidence
is retained as an issue. Billed request parts remain untouched. Missing metadata
does not block the shared native pricing path or justify adding T3 Usage totals.

Native files freeze their byte lengths before parsing. Metadata after that view
(completion, usage or selection timestamps) cannot join it. SQLite's separate
start/finish bounds are reported. A provider-thread projection updated during scanning needs a matching earlier provider-thread event to establish its session owner inside the native bound. Database/WAL/schema/resource failures retain
native usage and report the gap. Read-only WAL access follows
[SQLite's requirements](https://www.sqlite.org/wal.html#read_only_databases): no
copying a live database alone, checkpointing, immutable flag or journal-mode
change. The read transaction provides
[snapshot isolation](https://www.sqlite.org/isolation.html).

## Idle comparison

[T3's idle predicate](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/orchestration-v2/IdleCompaction.ts)
requires the latest completed run of a listed Claude main thread, its active
session/instance, at least 200,000 tokens and observed `promptCacheExpiresAt`.
Archived, deleted, settled, snoozed, subagent/side-chat threads, pending requests,
merge-backs and background work block the timer. A `/compact` run cannot arm
another compaction. Fully cached requests can omit the TTL, which is unknown,
not a one-hour default. Both 5m and 1h caches are supported. The timer starts two
minutes before expiry and cannot run after expiry.

The projection supplies current lifecycle guards only. It cannot prove prior
guard states, an in-memory timer surviving a restart, or unlogged/discarded
summary generation. Explicit idle run identity is preferred and travels through
the shared native summary/boundary linker. Otherwise a priced proactive scenario
is conditional on the verified current guards and server staying alive. Unknown
guards/expiry stay unpriced. An observed boundary is not required for the
conditional final-summary estimate, and absence never proves free activity.

[T3's resume handler](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts)
returns `continue` immediately for `off`. Other modes allow the SDK's
`resume_return` dialog. The cost scenario assumes that dialog is offered on a
cold eligible return and the user accepts; its offer criteria and acceptance
are not inferred as historical facts. It charges no final on-return summary.

The existing window/cache simulation supplies both current and post-recommendation
baselines. An unresolved effective window, including inherited per-model or launch
controls, leaves both idle baselines unpriced and advisory. Compatible native
summary output and full resumed-prefix samples calibrate hypothetical compaction,
including system/retained/new context. Shared
API pricing charges warm/cold summary input, output and all later changed prefixes.
Offsets carry through subsequent requests until an unrelated observed compaction
converges the paths. Recorded idle replacement is undone for the `off` alternative;
an unlinked recorded replacement stays unpriced. Final proactive summaries pay
without a return benefit. The lowest fully priced aggregate conditional cost wins;
equal costs keep the current mode. Period summary cost/calibration describe the proactive scenario; each mode has its separate aggregate cost. Independent setting savings do not add.

Synthetic tests cover settings precedence, disabled/shared/shadow homes, requested
versus billed speed, unique/duplicate/missing/bounded joins, optional schema/WAL
failure, consistent concurrent-WAL snapshots, all policies, five-minute caches,
cold returns, final/censored periods, missing calibration, and privacy sentinels.

Known native Claude REPL provenance and Codex `cli`/`exec` provenance can exclude
T3 ownership when a native profile is selected and no T3 link conflicts. Codex
app-server `vscode` provenance remains shared: the upstream
[app-server entrypoint](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/main.rs)
defaults to that source. A `--t3-dir`-only selection still selects configured native
history directories, not a proven T3-session-only filter; retained shared records
keep a named advisory profile rather than becoming anonymous charges.

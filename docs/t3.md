# T3 evidence

The adapter was checked against T3 Code commit
[c4ce7b0](https://github.com/pingdotgg/t3code/commit/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165)
on 2026-11-08. It supports that revision's `providerInstances` settings envelope,
legacy `providers`, and V2 projection tables. Unknown providers are excluded
before their unrelated controls are decoded. Malformed supported controls or
unknown global policy values fail with a path-only diagnostic. Unknown/missing
projection schemas disable optional metadata without removing
native billed requests. This is not a complete T3 bill.

## Discovery and controls

[Server paths](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/config.ts)
place production state in `.t3/userdata` and development state in `.t3/dev`.
`T3CODE_HOME` selects the base, while `--t3-dir` selects a state directory directly.
Configured homes expand `~`; inherited environment paths remain literal, matching
[Claude home resolution](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/provider/Drivers/ClaudeHome.ts).
Codex uses its configured/shared home, or the inherited `CODEX_HOME` fallback
without a managed/shadow home. Its
[shadow layout](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/provider/Drivers/CodexHomeLayout.ts)
shares native histories and config; it does not add another bill. Canonical file
walks and native request identities handle overlapping homes and aliases.

The allowlist reads home paths, enabled state, idle controls, Claude window and
launch arguments. Environment values are decoded only for home,
cache, provider, compaction and Bash controls used by existing checks; secret or
sensitive relevant entries make ownership unresolved. Arbitrary values and
credential references are not decoded or exported. Claude launch arguments are
parsed as T3's
[`parseCliArgs`](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/packages/shared/src/cliArgs.ts)
does, only to find `--settings` or `--setting-sources`, the flags that can replace
the settings Claude Code reads; either makes ownership unresolved. Any Codex
launch arguments do, since they can override any config key. Launch argument
text is not retained. Desktop connection catalogs are not read.

[Settings](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/packages/contracts/src/settings.ts)
resolve global `idleCompaction`, then legacy `compactIdleThreads` (`true` means
`beforeCacheExpires`, `false` means `onReturn`), defaulting to `onReturn`.
Per-instance `default` inherits that global value. Either enabled flag can disable
an instance without deleting its history. A machine policy may replace settings
or homes: presence/access errors on Linux/macOS and unsupported Windows registry
policy make current ownership advisory and discovery coverage explicitly incomplete.

Claude's SDK window override takes precedence over native user/project windows.
Without it, T3 passes no window, so Claude Code reads the native user, project
and local files; the instance's window checks use its home's settings, and its
idle check resolves each recorded project as a native profile does, under the
instance's environment. A recorded project that no longer exists leaves its
window unresolved. The
[Claude model compiler](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/claudeModelOptions.ts)
sets supported `fastMode` explicitly, default false. The
[Codex compiler](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/codexModelOptions.ts)
passes a selected service tier (or legacy fast selection); omission can inherit
native `service_tier`. Historical metadata does not establish the current thread
or browser composer selection. Unsupported/omitted historical capability data is
not converted into a billed speed.

## Text generation

T3 writes thread titles, branch names, PR text, review guides and dictation
cleanup with `textGenerationModelSelection`. Unset, it is
[instance `codex`, `gpt-6-luna`, low effort](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/packages/contracts/src/settings.ts).
The [server](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/serverSettings.ts)
keeps a selection whose text generator or instance is enabled; otherwise it
falls back to the first enabled default instance in its driver order, using
the [driver's text model](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/packages/contracts/src/model.ts)
or the thread default when that is one of the instance's custom models.
[Source control writing, review guides and dictation cleanup](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/packages/shared/src/serverSettings.ts)
replace it when their own selection is usable; review guides never use a text
generator. Projects can replace these selections, so the report counts the
projects that do rather than resolving each one. Provider availability is not
known with the server closed and is assumed, as T3 does without provider
snapshots.

The cost is unmeasured. [Codex](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/textGeneration/CodexTextGeneration.ts)
runs `codex exec --ephemeral`, [Claude](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/textGeneration/ClaudeTextGeneration.ts)
runs with `--no-session-persistence`, and text generators call a model API
directly, so no native record holds the spend. A Claude CLI too old for that
flag keeps its sessions, which are priced as ordinary native requests and not
attributed to text generation.

## SQLite and native links

The adapter opens only an existing `statev2.sqlite` with SQLite read-only flags,
zero busy timeout, `query_only` and `trusted_schema=OFF`. It holds one read
transaction across schema validation and all allowlisted queries. Its bundled
SQLite needs no external installation. Native identities exist privately until
joining; exported thread/run/attempt/turn identities are opaque hashes.

T3 indexes no Claude native identity, so one pass over provider threads maps
the selected native sessions to their T3 threads. Every other lookup follows
T3's indexes from those threads, so the read grows with the selected history,
not the database. Claude requests join turn items by their native ids: the
record uuid of text, the tool-use id of a tool call, and the message id of
`<message id>:thinking:<n>` reasoning. T3 derives each turn item id from that
native id, so the join reads ids only, never item payloads, which hold tool
outputs. Duplicate matches stay ambiguous. Real table
presence is validated before queries. Malformed or orphan join rows remain
unavailable/ambiguous individually, preserving other valid joins. SQLite value
lengths are limited to 1 MiB. A failed read is optional metadata
unavailability, never a zero-cost claim, and the report names its cause:
schema, the value-length resource bound, or database/WAL access. SQL may
compare exact `/compact` markers but returns no message text, tool arguments,
outputs or arbitrary JSON payloads.

Native provider thread/session and turn/item identities must join uniquely through
the same thread/provider-thread/attempt. Requested speed comes only from the first
V2 `run.updated` running event for that exact attempt and matching model. A later
steering event cannot fill an absent first selection. Conflicting native evidence
is retained as an issue. Billed request parts remain untouched. Missing metadata
does not block the shared native pricing path or justify adding T3 Usage totals.
Native and T3 requested tiers use the shared pricing aliases and preserve each
other's nonconflicting fields. When the effective Codex tier is missing, these
historical selections can choose a conditional API estimate; they never establish
the billed tier or resolve tier-sensitive recommendations.

Native files freeze their byte lengths before parsing. Metadata after that view
(completion, usage or selection timestamps) cannot join it. SQLite's separate
start/finish bounds are reported. A provider-thread projection updated during scanning needs a matching earlier provider-thread event to establish its session owner inside the native bound. Database/WAL/schema/resource failures retain
native usage and report the gap. Read-only WAL access follows
[SQLite's requirements](https://www.sqlite.org/wal.html#read_only_databases): no
copying a live database alone, checkpointing, immutable flag or journal-mode
change. The read transaction provides
[snapshot isolation](https://www.sqlite.org/isolation.html).

## Idle comparison

[T3's idle predicate](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/orchestration-v2/IdleCompaction.ts)
requires the latest completed run of a listed Claude main thread, its active
session/instance, at least 200,000 tokens and observed `promptCacheExpiresAt`.
Archived, deleted, settled, snoozed, subagent/side-chat threads, pending requests,
merge-backs and background work block the timer. A `/compact` run cannot arm
another compaction. A fully cached last request reports no TTL, so T3 arms no
timer for it. Both 5m and 1h caches are supported.
[T3 dates expiry](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts)
from the request start. The
[timer](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/orchestration-v2/IdleCompactionService.ts)
starts two minutes before expiry, at once when the run completes inside that
lead, and cannot run after expiry. So no gap shorter than three minutes from its
request's start can trigger it, joined to T3 or not.

The projection supplies current lifecycle guards only. It cannot prove prior
guard states, an in-memory timer surviving a restart, or unlogged/discarded
summary generation. Explicit idle run identity is preferred and travels through
the shared native summary/boundary linker. Otherwise a priced proactive scenario
is conditional on the verified current guards and server staying alive, so a gap
before a later run in the same thread stays unpriced. Unknown guards/expiry stay
unpriced. An observed boundary is not required for the conditional final-summary
estimate, and absence never proves free activity.

[T3's resume handler](https://github.com/pingdotgg/t3code/blob/c4ce7b0fd74f6beb37ed6034f5c8416e5aa7e165/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts)
returns `continue` immediately for `off`. Other modes allow the SDK's
`resume_return` dialog. The cost scenario assumes that dialog is offered when a
new T3 run resumes a session of at least 200,000 tokens after its cache lifetime
and the user accepts; its offer criteria and acceptance are not inferred as
historical facts. The dialog belongs to the SDK, so it needs no T3 lifecycle
guard or recorded expiry, only both requests' T3 runs, the context size and the
effective TTL. It charges no final on-return summary.

The existing window/cache simulation supplies both current and post-recommendation
baselines. An unresolved effective window, such as one a `--settings` launch
argument can replace, leaves both idle baselines unpriced and advisory. Compatible native
summary output and full resumed-prefix samples calibrate hypothetical compaction,
including system/retained/new context. Shared
API pricing charges warm/cold summary input, output and all later changed prefixes.
Offsets carry through subsequent requests until an unrelated observed compaction
converges the paths. Recorded idle replacement is undone for the `off` alternative;
an unlinked recorded replacement stays unpriced. Final proactive summaries pay
without a return benefit. Each mode's cost is the change it makes to the
recorded history; requests no mode changes cancel, so their missing usage or
prices never block the comparison. The lowest fully priced aggregate conditional
cost wins; equal costs keep the current mode. An unpriced line prices the modes
it can and names the first input the others lack, the window or ownership first. Period summary cost/calibration describe the proactive scenario; each mode has its separate aggregate cost. Independent setting savings do not add.

Synthetic tests cover settings precedence, disabled/shared/shadow homes, requested
versus billed speed, unique/duplicate/missing/bounded joins, optional schema/WAL
failure, consistent concurrent-WAL snapshots, all policies, five-minute caches,
cold returns, final/censored periods, timer bounds, missing calibration or
guards, cancelling unrelated gaps, text-generation resolution, and privacy
sentinels.

Known native Claude REPL provenance and Codex `cli`/`exec` provenance can exclude
T3 ownership when a native profile is selected and no T3 link conflicts, even
if T3's state was not read. Codex app-server `vscode` provenance does not, since
T3 runs the app-server and the upstream
[app-server entrypoint](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/main.rs)
defaults to that source. A subagent shares its root session's owner: a Claude
subagent file records its parent's session id, and a Codex subagent thread
names its root as `session_id` or its parent as `parent_thread_id`. Ownership
counts only requests inside the window; earlier context never unresolves a
profile. Once T3's state is read, a session with no T3 provider thread belongs
to the native profiles unless its client label is one T3's provider adapters
write: Claude `sdk-ts` (the Agent SDK default) or `t3-code`, Codex originator
`T3 Code`, or no label at all. A T3 provider session lacks a thread only if T3
dropped it, so such a label keeps it shared. A subagent whose root session
excluded T3 excludes it too. Each request that stays
unresolved is counted under its cause in `scan.t3[].unresolved` and on a
`T3 unresolved` report line. A `--t3-dir`-only selection still selects configured native
history directories, not a proven T3-session-only filter; retained shared records
keep a named advisory profile rather than becoming anonymous charges.

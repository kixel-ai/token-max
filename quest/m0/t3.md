# [L] T3 profiles, settings, and policy evidence

## Goal

`token-max` includes T3's Claude Code and Codex instances in its existing
cost/settings report, discovers their native histories without double
counting, and identifies T3-owned controls instead of recommending edits
to an overridden native setting. T3 idle policies use their own semantics.
Processing stays read-only and never exposes conversation or credential text.

## Plan

Requested 2026-11-07 through /quest-plan. The maintainer subsequently said
"afk spawn and merge whatever you want", delegating the recommended scope
and implementation choices. ✅ Include T3's Claude/Codex instances in m0
(rejected: deferring this support or adding parsers for every T3 provider).
The existing checks remain the analysis owners; this is their T3 adapter,
not a second billing implementation or a change to T3 itself.

- Discover the default T3 state and explicit repeatable T3 state roots,
  including configured provider homes and allowlisted environment overrides.
  Include disabled instances' retained histories, but distinguish their
  historical spend from active current settings. Reuse canonical native
  roots, request identities, profile aliases and shared-history attribution.
  Codex shadow/shared homes can expose the same sessions. Unsupported T3
  providers appear as exclusions rather than an implied complete T3 bill.
- Read only profile/control fields needed by the report, not credentials,
  arbitrary environment values or the desktop connection catalog. Native
  transcripts remain the billed-request source; never add T3's aggregate
  Usage totals to them. Custom roots and ownership must work with T3 closed.
- Resolve effective T3 versus native precedence from verified driver/schema
  behavior. Cover window, speed and idle controls, and identify native-only
  features that do not apply to T3's client. Carry the owning instance/tool
  through the existing checks and renderer. Current overrides do not prove
  historical settings or billed speed. Speed belongs to per-thread model
  selection, not a T3 profile speed key: Claude's explicit `fastMode` defaults
  false and overrides native settings, while Codex can inherit native
  `service_tier` when no fast selection is passed. The new-thread composer
  default lives in browser storage; unavailable current state stays advisory.
- Use read-only T3 lifecycle/run projections where supported to attach
  allowlisted metadata through unique native session/turn/request/run links.
  Keep requested speed distinct from actual billed speed. Ambiguous joins,
  missing optional history and unsupported evidence stay explicit; they do
  not supply invented usage, eligibility or zero cost. Use bounded metadata
  queries, not a full database copy or conversation export. Read SQLite
  through `rusqlite` with its bundled library, so no system SQLite is
  required. Open an
  existing database read-only and hold one read transaction across the
  allowlisted queries for a consistent WAL snapshot, closing it before
  analysis. Never copy a live database alone, checkpoint it, mark it immutable
  or change its journal mode. Validate schemas and report unavailable WAL
  access safely. Native transcript and database snapshots have distinct
  bounds; do not join evidence beyond either captured view.
- Extend the existing idle-policy comparison for T3's `onReturn`,
  `beforeCacheExpires` and `off` controls. Verify its observed-expiry timer,
  token threshold, main-thread/lifecycle guards and effective cache TTL;
  do not reuse native Claude's interactive-client or 1h-only eligibility.
  Prefer explicit idle run identities and observed outcomes, retaining
  uncertainty about unlogged generation and user acceptance on return.
  Price warm/cold summaries, full resumed prefixes and final summaries,
  then recommend the aggregate estimated net winner under the existing
  estimation policy. Name the T3 control and conditional baseline. Resolve
  global `idleCompaction`, its legacy `compactIdleThreads` fallback and
  per-instance `default` inheritance. Configured proactive mode does not
  prove generation: its in-memory timers are lost on server restart. T3's
  `off` also suppresses Claude's resume prompt.
- T3 auxiliary generation can use ephemeral sessions. Expose the coverage
  gap for titles/branches/PR text and other helpers unless retained billing
  evidence verifies their cost. Do not classify them as native suggestions,
  recaps or free activity from absent native records.
- Test synthetic supported T3 settings/projection shapes, effective-owner
  conflicts, shared/shadow homes, unique and ambiguous joins, all idle modes,
  expired caches, unresumed work, unavailable metadata and privacy. No real session becomes a fixture.
